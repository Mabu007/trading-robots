# Phase 2 · Production SDK chat

The main Chat composer defaults to the AI SDK transport with Firebase authentication and the user's selected OpenRouter connection. The former transport is available with `VITE_AI_SDK_CHAT_ENABLED=false`. Both transports preserve existing conversation records and workspace cards. The SDK planner can propose a workspace action. Only the corresponding application controls can authorize a mutation.

- A named saved strategy discussion reads the exact owner-scoped R2 source on the server. Public market research produces its own source-labelled evidence. Selected market, strategy, simulation, broker metadata, runtime and monitor tools are bounded by turn limits. Broker metadata is not live account readiness.
- The Hyperliquid server simulation uses completed exact-instrument history, isolated QuickJS, and a shared quota across both SDK and direct entry points. The existing PropDAO, cTrader and VALR workspace paths retain their historical-data semantics and result cards. A Hyperliquid simulation does not substitute for those venues.
- A successful SDK read can attach a receipt persisted by the server in Firestore. Conversation history stores the receipt ID. Restoring a conversation resolves receipts using the authenticated owner and conversation ID. Receipt data is separate from client-editable conversation text and does not grant authorization.
- Stop response aborts the planner, read or stream where the underlying request supports cancellation and prevents a late result from replacing chat content. Switching chats first settles the stopped turn. Native backtests use the existing backtest cancellation control. Once a confirmed write or workspace handoff starts, the UI waits for its result.
- A saved strategy edit stages the exact old and proposed source before showing the review. Deny and Confirm are distinct server operations. Approval binds owner, strategy, instrument, venue, source hashes, operation and expiry, and apply consumes it once under the existing write locks. cTrader source changes still require verified stopped gateway state. Model tools do not approve or execute financial actions.

Production environment uses `AI_SDK_STRATEGY_APPROVAL_ENABLED=true` and `AI_SDK_SERVER_BACKTEST_ENABLED=true` with Firebase and R2. No shared OpenRouter key is needed for normal operation. See [issue #62](https://github.com/Mabu007/trading-robots/issues/62) for production browser evidence and release status.
